# 计算机组成原理 第2讲（续） 过程调用与非叶子过程

## 本讲提纲 (Outline)
- 过程调用 (Procedure Call)
- 非叶子过程 (Non‑Leaf Procedure)

---

## 过程调用 (Procedure Calling)

在高级语言中，函数调用是基本的结构。在汇编层面，这一过程需要精确的协作步骤。

### 调用函数的六个步骤
1. 将**参数**放到过程能访问到的地方。
2. 将**控制权**转移给过程。
3. 获取过程所需的**存储资源**。
4. 执行**目标任务**。
5. 将**返回值**放到调用程序能访问的地方。
6. 将**控制权返回到调用点**，因为一个过程可能从程序中多处被调用。

---

## 内存布局 (Memory Layout)

为了支持上述步骤，程序在内存中按照约定的布局进行组织：

- **代码段 (Text)**：存放指令（二进制程序代码）。
- **静态数据段 (Static data)**：全局变量，例如 C 中的 `static` 变量、常量数组和字符串。  
  全局指针 (Global Pointer, `gp`) 通常初始化为该段内地址，允许通过 `gp` 加上正负偏移量访问该段。
- **动态数据段 (Dynamic data)**：堆 (Heap)，用于动态分配，例如 C 中的 `malloc`、Java 中的 `new`。
- **栈 (Stack)**：自动存储，用于局部变量、保存的寄存器等，随着过程调用和返回而自动增长/收缩。

---

## 参数和返回值放在哪儿？ (Where to Put Arguments and Return Values?)

- **寄存器比内存快得多**，因此只要有可能，就优先使用寄存器。
- 符号化寄存器名称及其用途：
  - `a0` – `a7` (对应 `x10` – `x17`)：用于传递函数参数，其中 `a0`–`a1` 也用于返回值。
  - `ra` (对应 `x1`)：返回地址寄存器，保存函数被调用的位置，以便执行完能返回。
- 如果需要额外的空间，则使用内存（即**栈**）。

---

## 程序计数器 (Program Counter, PC)

- **PC (程序计数器)** 是处理器内部一个特殊的寄存器，存放**下一条将要执行的指令的字节地址**。
- 指令从内存取出后，控制单元使用数据通路和存储系统执行该指令，并更新 PC（默认是 **PC ← PC + 4**，跳转到下一条顺序指令）。

---

## RISC‑V 寄存器与约定 (RISC‑V Registers and Convention)

为了统一不同编译器生成的代码之间的接口，**ABI (Application Binary Interface，应用程序二进制接口)** 定义了 **“调用约定” (Calling Convention)**。从此我们将使用 ABI 名称，不再直接写 `x3`、`x6` 等。

| 寄存器 | ABI 名称 | 描述 | 是否由被调用者保存？ |
| :--- | :--- | :--- | :---: |
| `x0` | `zero` | 常数 0 | N/A |
| `x1` | `ra` | 返回地址 | 否 |
| `x2` | `sp` | 栈指针 (Stack Pointer) | 是 |
| `x3` | `gp` | 全局指针 (Global Pointer) | N/A |
| `x4` | `tp` | 线程指针 (Thread Pointer) | N/A |
| `x5 – x7` | `t0 – t2` | 临时寄存器 (Temporaries) | 否 |
| `x8` | `s0 / fp` | 保存寄存器 / 帧指针 (Frame Pointer) | 是 |
| `x9` | `s1` | 保存寄存器 | 是 |
| `x10 – x17` | `a0 – a7` | 函数参数 / 返回值 | 否 |
| `x18 – x27` | `s2 – s11` | 保存寄存器 | 是 |
| `x28 – x31` | `t3 – t6` | 临时寄存器 | 否 |

> “由被调用者保存” 这一列的含义将在调用约定部分详细解释。

---

## 控制转移 (Transfer Control)

过程调用和返回通过两条特殊指令实现：

- **过程调用：跳转并链接 (`jal`, Jump and Link)**  
  - 实际顺序是 “链接再跳转”：先将返回地址存入 `ra`，再跳转到目标地址。  
  - 伪码形式：`jal ra, target` 或简写为 `jal target`。  
  - 下一条指令的地址（返回地址）被保存到 `ra`，然后 PC 跳转到目标地址。  
  - 由**调用者 (Caller)** 使用。

- **过程返回：寄存器跳转并链接 (`jalr`)**  
  - 伪码形式：`jalr zero, 0(ra)` 或简写为 `jr ra`。  
  - 同 “跳转并链接” 类似，但目标地址来自寄存器（这里是 `ra`），同时将下一指令地址保存到 `zero` 寄存器（即丢弃该保存）。  
  - 由**被调用者 (Callee)** 使用。

**示例**
```assembly
1000 addi a0, s0, 0   # 传递参数 x → a0
1004 addi a1, s1, 0   # 传递参数 y → a1
1008 jal  sum         # ra = 1012, 跳转到 sum
1012 …                # 返回后的下一条指令
...
2000 sum: add a0, a0, a1
2004      jr ra       # 返回到 1012
```
PC (十进制) 的变化：... → 1000 → 1004 → 1008 → 2000 → 2004 → 1012 → ...

## 局部变量的存储 —— 栈 (Local Storage for Variables – Stack)

- 当寄存器不够用，或局部变量的地址需要被引用时，使用**栈**来存放**自动局部变量**。
- 基本操作：
  - **压栈 (Push)**：将数据放入栈顶。
  - **弹栈 (Pop)**：从栈顶取出数据。
- `sp` (栈指针, `x2`) 始终指向栈中**最后被使用的位置**。
  - 压栈时 `sp` 减小（向低地址增长），`sp ← sp – size`。
  - 弹栈时 `sp` 增大，`sp ← sp + size`。

## 叶子过程示例 (Leaf Procedure Example)

**叶子过程**是指不再调用其他函数的过程，因此它是单纯地被调用者。  
C 代码：
```c
int leaf_example(int g, int h, int i, int j) {
    int f;
    f = (g + h) - (i + j);
    return f;
}
```

假设：参数 `g, h, i, j` 分别对应寄存器 `a0, a1, a2, a3`，变量 `f` 使用 `s4`，临时变量用 `t0, t1`。

**初始版本汇编**（严格按照书本习惯）：
```assembly
leaf_example:
    addi sp, sp, -12   # 在栈上开辟 12 字节空间
    sw   t1, 8(sp)     # 保存 t1
    sw   t0, 4(sp)     # 保存 t0
    sw   s4, 0(sp)     # 保存 s4（因为 s4 是 callee‑saved）
    add  t0, a0, a1    # t0 = g + h
    add  t1, a2, a3    # t1 = i + j
    sub  s4, t0, t1    # f = t0 - t1
    add  a0, s4, zero  # 置返回值 a0 = f
    lw   s4, 0(sp)     # 恢复 s4
    lw   t0, 4(sp)     # 恢复 t0
    lw   t1, 8(sp)     # 恢复 t1
    addi sp, sp, 12    # 释放栈空间
    jr   ra            # 返回
```

### 为什么要保存和恢复寄存器？

- `t0`‑`t6` 是**调用者保存**，但这里作为被调用者，如果使用了它们，为了不影响调用者，可以选择保存恢复。然而叶子过程没有进一步调用，所以调用者若需要这些值，调用者自己会保存。所以对于叶子过程，**实际上无需保存 `t0, t1`**。
- `s0`‑`s11` 是**被调用者保存**：如果被调用者要使用这些寄存器，必须保存原值，并在返回前恢复。

### 优化版本
利用调用约定，可以避免不必要的保存操作：
- `a0` 可直接作返回值，无需通过 `s4`。
- 无需保存 `t0, t1`，因为它们是调用者保存寄存器，且此处没有更深的调用，调用者若在意会自行保存。
优化后的汇编：
```assembly
leaf_example:
    add  t0, a0, a1   # t0 = g + h
    add  t1, a2, a3   # t1 = i + j
    sub  a0, t0, t1   # a0 = (g+h) - (i+j) 即为返回值
    jr   ra
```
栈空间完全未使用，代码既快又短。

## 调用约定 (Calling Convention)

调用约定可以理解为函数之间的**契约**，明确了寄存器使用的责任方：

- **调用者保存寄存器 (Caller‑saved)**
  - 如果调用者希望在这些寄存器中的值在调用后仍然有效，则**调用者**必须在调用前保存它们。
  - 包括：`a0`–`a7` (参数/返回值), `t0`–`t6` (临时寄存器), `ra` (返回地址)。
- **被调用者保存寄存器 (Callee‑saved)**
  - 被调用者在使用这些寄存器之前，必须先保存它们的原始值，并在返回前恢复。
  - 包括：`s0`–`s11` (保存寄存器), `sp` (栈指针)，以及帧指针 `fp`(s0) 等。

> 叶子过程示例中我们看到了：因为要使用 `s4`，所以被调用者必须保存并恢复它。而优化后不碰 `s` 寄存器，也就不需要。

## 非叶子过程 (Non‑Leaf Procedure)

非叶子过程是指**会调用其他过程的过程**（包括递归调用自身）。因为自身还会再发起调用，与叶子过程不同，它必须更小心地保护某些数据。

### 过程帧 (Procedure Frame / Activation Record)
- 许多编译器在栈上为每个过程调用维护一个**活动记录 (Activation Record)**，也称过程帧。
- **帧指针 (`fp`)** 通常指向帧的起始位置（某些编译器优化后不一定使用）。
- **栈指针 (`sp`)** 指向帧的末端——随着过程内临时数据的压栈弹栈而动态变化。

### 非叶子过程的关键需求
对于嵌套调用（包括递归）：
- **调用者在调用前**必须在自己的栈帧中保存：
  - 它的返回地址 `ra`（因为 `jal` 会覆盖 `ra`）
  - 任何在调用后还需要的参数和临时寄存器（即调用者保存寄存器中有用的值）
- 调用返回后，再从栈中恢复这些值。

---

## 非叶子过程示例：递归阶乘 (Non‑Leaf Procedure Example)

下面以经典的**递归阶乘**为例，详细解释非叶子过程如何运作。

C 代码：
```c
int fact(int n) {
    if (n < 1) return 1;
    else return n * fact(n - 1);
}
```

### 汇编实现与逐步解释

```assembly
fact:
    addi sp, sp, -8      # ① 在栈上分配 8 字节空间 (两个寄存器的大小)
    sw   ra, 4(sp)       # ② 保存返回地址 ra (因为接下来 jal 会覆盖它)
    sw   a0, 0(sp)       # ③ 保存当前参数 n (调用后还需要用于乘法)

    slti t0, a0, 1       # ④ 若 n < 1，则 t0 = 1，否则 t0 = 0
    beq  t0, zero, L1    # ⑤ 如果 t0 == 0 (即 n >= 1)，跳转到 L1 (递归情形)
                         #    否则顺序执行 (基准情形)

    # ----- 基准情形 n < 1 -----
    addi a0, zero, 1     # ⑥ 返回值设为 1
    addi sp, sp, 8       # ⑦ 释放栈空间 (基准情形未使用保存的值，直接丢弃)
    jr   ra              # ⑧ 返回

L1:
    # ----- 递归情形 n >= 1 -----
    addi a0, a0, -1      # ⑨ 参数变为 n-1
    jal  fact            # ⑩ 递归调用 fact(n-1)
                         #     此时 ra 被覆盖为下条指令地址
                         #     返回值在 a0 中 (即 fact(n-1) 的结果)
    addi t1, a0, 0       # ⑪ 将返回值暂存到 t1 (调用者保存，但我们需要它)
    lw   a0, 0(sp)       # ⑫ 从栈中恢复原参数 n (之前保存的)
    lw   ra, 4(sp)       # ⑬ 从栈中恢复返回地址 (因为已被 jal 破坏)
    addi sp, sp, 8       # ⑭ 释放栈帧
    mul  a0, a0, t1      # ⑮ 计算 n * fact(n-1)，结果放入 a0 作为返回值
    jr   ra              # ⑯ 返回
```

**为什么需要保存 `a0` 和 `ra`？**
- `ra` 在 `jal fact` 执行后会被覆盖为本函数的返回地址，而我们需要返回原来调用者的地址，所以必须提前保存在栈上。
- 参数 `n` (存放在 `a0`) 在调用 `fact(n-1)` 后会改变，但乘法 `n * fact(n-1)` 还需要原来的 `n`，因此也必须保存。

### 执行流程追踪（假设调用 `fact(2)`）

1. 外部调用 `fact(2)` 时，`a0=2`，`ra` 指向调用者返回地址。
2. 执行 `fact`：分配栈帧，保存 `ra` 和 `a0=2`。  
   `slti t0,2,1` → `t0=0`，`beq t0,zero,L1` 跳转到 L1（递归情形）。
3. `a0 = 2-1 = 1`，`jal fact` 递归调用自身。  
   - 进入第二层 `fact(a0=1)`：再次分配栈帧，保存新的 `ra` 和 `a0=1`。  
   - `slti t0,1,1` → `t0=0`，跳到 L1。  
   - `a0 = 0`，`jal fact` 再次调用。
4. 进入第三层 `fact(0)`：分配栈帧，保存 `ra` 和 `a0=0`。  
   `slti t0,0,1` → `t0=1`，`beq` 不成立，顺序执行基准情形。  
   `a0=1`，释放栈帧，`jr ra` 返回到第二层 `L1` 之后。
5. 第二层恢复执行：`t1 = 1` (返回值)，从栈恢复 `a0=1` 及 `ra`，释放栈帧，  
   `mul a0, 1, 1` → `a0=1`，`jr ra` 返回到第一层。
6. 第一层恢复：`t1 = 1`，恢复 `a0=2`，释放栈帧，  
   `mul a0, 2, 1` → `a0=2`，返回到最初调用者。

整个过程清晰地展示了**栈如何自然支持递归保存每一层的上下文**。

## 总结

1. 函数调用使用 `jal`，返回使用 `jalr` (或伪指令 `jr ra`)。
2. **栈是你的朋友**：用它保存需要跨调用持有的任何数据，但要记得在返回前恢复原状。
3. 迄今为止掌握的指令类别：
   - 算术指令
   - 访存指令
   - 条件分支指令
   - 无条件跳转指令
4. **寄存器约定**：理解调用者保存与被调用者保存是书写正确汇编代码的核心。
