# 第3讲：指令编码、分支跳转与不同ISA

## 本讲提纲 (Outline)
- 指令编码格式 (Instruction Encoding Formats)
- 分支与跳转寻址 (Branch and Jump Addressing)
- 大立即数 (Large Immediate)
- 不同的指令集架构 (Different ISAs)

---

## 指令即数字 (Instructions as Numbers)

- 我们处理的大部分数据都是**字 (Word)**（32 位块）：每个寄存器保存一个字，`lw` 和 `sw` 每次以字为单位访问内存。
- 那么**指令**如何表示？记住：计算机只认 0 和 1，像 `add x10, x11, x0` 这样的汇编代码对硬件毫无意义。
- RISC‑V 追求简洁：既然数据以字为单位，那么就让指令也是**固定大小 32 位字**。
- 相同的 32 位指令定义同时适用于 RV32、RV64 和 RV128。

---

## 指令的二进制格式 (Instructions in Binary)

- 将 32 位指令字划分为若干**字段**，每个字段告诉处理器关于指令的部分信息。
- 我们本可以为每条指令定义不同的字段，但为了硬件简洁，RISC‑V 把可能的指令归类为**六种基本指令格式**：
  - **R‑格式 (R‑format)**：寄存器‑寄存器算术/逻辑操作
  - **I‑格式 (I‑format)**：寄存器‑立即数 ALU 操作及载入指令
  - **S‑格式 (S‑format)**：存储指令
  - **B‑格式 (B‑format)**：分支指令（教材中也称 SB 格式）
  - **U‑格式 (U‑format)**：20 位高位立即数指令
  - **J‑格式 (J‑format)**：跳转指令（教材中也称 UJ 格式）

---

## R 型指令格式 (R‑Type)

R‑格式用于**寄存器‑寄存器**算术/逻辑操作，例如 `add`、`sub`、`slt`、`sltu`、`sll`、`srl`、`sra`、`and`、`or`、`xor` 等。

### 字段划分
32 位指令字被划分为六个长度不同的字段：7 + 5 + 5 + 3 + 5 + 7 = 32 位。

| 字段 | 位宽 | 位置 (位) | 含义 |
| :--- | :--- | :--- | :--- |
| `opcode` | 7 位 | 位 0–6 | 操作码，部分指明是哪类指令。所有 R‑格式算术/逻辑指令的 `opcode` 均为 `0110011`。 |
| `rd` | 5 位 | 位 7–11 | 目标寄存器 |
| `funct3` | 3 位 | 位 12–14 | 进一步区分操作类型 |
| `rs1` | 5 位 | 位 15–19 | 第一源操作数寄存器 |
| `rs2` | 5 位 | 位 20–24 | 第二源操作数寄存器 |
| `funct7` | 7 位 | 位 25–31 | 与 `funct3`、`opcode` 一起指定具体操作 |

- **为何不把 `opcode`、`funct7`、`funct3` 合并成一个 17 位字段？** 这样可以让某些指令复用同一 `opcode`，简化译码电路，后续会详细解释。

### 寄存器字段 (`rs1`, `rs2`, `rd`)
- 每个寄存器字段是一个 5 位无符号整数 (0–31)，对应寄存器 `x0`–`x31`。
- `rs1` (源寄存器1)：存放第一个操作数
- `rs2`：存放第二个操作数
- `rd` (目的寄存器)：存放计算结果

### R‑Type 编码示例 1：汇编 → 机器码
**`add x18, x19, x10`**  
- `rd = x18 = 18`，`rs1 = x19 = 19`，`rs2 = x10 = 10`  
- `opcode = 0110011`，`funct3 = 000`，`funct7 = 0000000`  
- 机器码：`0x00a98933`

### R‑Type 编码示例 2：机器码 → 汇编
**机器码 `0x01B342B3`**  
- 二进制：`0000 0001 1011 0011 0100 0010 1011 0011`  
- 最低 7 位 `0110011` → R‑格式  
- 从右向左解析各字段，得到：  
  答案：**`xor x5, x6, x27`**

## I 型指令格式 (I‑Type)

如果指令带有立即数该怎么办？比如 `addi x7, x5, 100`。  
理想情况下 RISC‑V 只有一种格式，但必须有所妥协。若用 R‑格式，`rs2` 和 `funct7` 合并也只能提供 5 位立即数（范围 0–31），太小；于是定义另一种格式，与 R‑格式高度一致。

### I‑格式字段
- `opcode`、`rd`、`funct3`、`rs1` 与 R‑格式完全相同。
- 不同之处：**`rs2` 和 `funct7` 被替换为 12 位带符号立即数 `imm[11:0]`**。
- `imm[11:0]` 的取值范围：\(-2^{11}\) 到 \(+2^{11}-1\) （即 -2048 ~ 2047）。
- 使用时，立即数会**符号扩展 (Sign‑Extended)** 至 32 位，再参与运算。

### I‑格式适用指令
- 寄存器‑立即数 ALU 操作：`addi`、`andi`、`ori`、`xori`、`slti`、`sltiu` 等
- 移位立即数：`slli`、`srli`、`srai`
- 载入指令：`lw`、`lh`、`lhu`、`lb`、`lbu` 等

### I‑Type 编码示例
**`addi x15, x1, -50`**  
- `rd = 15`，`rs1 = 1`，立即数 = -50  
- 机器码：`0xfce08793`

### 载入指令也是 I‑型
- `lw rd, immediate(rs1)`  → `rd = Mem[rs1 + imm]`
- 12 位立即数 `imm` 与基址寄存器 `rs1` 相加得到内存地址。这与 `addi` 类似，但用于生成地址而非最终计算结果。
- 加载的值存入寄存器 `rd`。

**I‑Type 载入示例**  
**`lw x14, 8(x2)`** → 机器码 `0x00812703`

### RV32 全部载入指令
- `lb`：加载字节，符号扩展
- `lbu`：加载无符号字节，零扩展
- `lh`：加载半字 (2 字节)，符号扩展
- `lhu`：加载无符号半字，零扩展
- `lw`：加载整字
- **RV32 中没有 `lwu`**，因为在 32 位存储单元与 32 位寄存器之间拷贝无需带符号/零扩展。
- 练习：将 `lbu x6, 4(x5)` 转换成机器码。

## S 型指令格式 (S‑Type Used for Stores)

存储指令需要两个源操作数（要存的值 + 基址），**不写目的寄存器**，因此格式与前不同。

**示例：`sw x14, 8(x2)`**
- `rs1 = x2`（基址寄存器），`rs2 = x14`（要存储的数据），偏移量 = 8
- 12 位偏移被拆成两段：`imm[11:5]` 放在指令的高 7 位，`imm[4:0]` 放在低 5 位（与 `rs2` 位置互换）。
- 机器码：`0x00812703`？实际 `sw` 的 opcode 是 `0100011`，应得 `0x00E12423`，此处原文示例可能有一处笔误，核心思路仍是偏移量字段拆分。

## 分支与跳转寻址 (Branch and Jump Addressing)

### RISC‑V 条件分支
- `beq rs1, rs2, Label`：若相等则分支。
- 典型用于 `if‑else`、`while`、`for`。
- 只读取两个寄存器，不写寄存器（类似存储指令）。
- **如何编码分支目标 `Label`？**  
  使用一个立即数作为 **PC 相对偏移量 (PC‑relative offset)**。
  - 如果不分支：`PC ← PC + 4`（顺序执行下一条）
  - 如果分支：`PC ← PC + 相对偏移量`

### PC 相对寻址 (PC‑Relative Addressing)
- 偏移量以**字节**为单位，可正可负。
- 用 12 位立即数编码偏移，原本可达 \(\pm 2^{11}\) 字节。
- 但 RISC‑V 指令都是 32 位，指令地址永远是 4 的倍数，即偏移最低 2 位始终为 0。
- 为扩大分支范围，RISC‑V 采用**半字单位**计算偏移：目标地址 = `PC + imm × 2`。
  - 这样可达 \(\pm 2^{12}\) 字节范围。
  - 使用半字而非字，是为了兼容可能的 16 位压缩指令。
- 因此，12 位立即数实际编码了一个 13 位有符号字节偏移（最低位始终为 0，无需存储）。

### B 型格式 (B‑Type for Branches)
- B‑格式与 S‑格式很像：两个源寄存器 `rs1`、`rs2` 和一个 12 位立即数。
- 立即数被重新排列以表示半字偏移量，实际跳转字节偏移 = `imm × 2`。

**B‑Type 示例 1：汇编 → 机器码**  
假设有如下 C 循环代码对应的汇编：
```assembly
Loop: beq  x19, x10, End
      add  x18, x18, x10
      addi x19, x19, -1
      j    Loop
End:
```
若将标签 `End` 换成数字偏移量：`beq x19, x10, 16`（16 字节，即 4 条指令远处）。
- 用 13 位表示 16，取高 12 位作为立即数字段进行编码。

**B‑Type 示例 2：机器码 → 汇编**  
给定 B‑格式机器码立即数 `imm[12:1] = 0000_0000_1000`  
→ 目标地址 = `PC + (imm[12:1] × 2) = PC + 16`  
得出汇编：**`beq x19, x10, 16`**。
- 问：移动代码后，分支立即数字段会变吗？  
  - 如果移动单行指令，会变；  
  - 如果整体移动所有代码，不变（因为 PC 相对偏移量保持不变）。

### 远距离分支：采用跳转 (Jump: Branching Far Away)
当分支目标超过 ±\(2^{10}\) 条指令范围时，可以：
- 将条件分支替换为无条件跳转 `j far`。  
- `j far` 本质是 `jal x0, far`（J‑格式，见后）。

示例代码：
```assembly
      beq x10, x0, far
      # 其他指令
far:  bne x10, x0, next
      j   far
next: # 后续指令
```

## J 型格式用于跳转 (J‑Type for Jump Instructions)

- `jal rd, Label`  
  - 伪指令 `j Label` 实质为 `jal x0, Label`。
- `JAL` 把 `PC+4` 保存到 `rd`（返回地址）。
  - `j` 则丢弃返回地址（`rd=x0`）。
- `PC ← PC + 偏移量`（PC 相对跳转）
- 使用**20 位立即数**，跳转范围达 \(\pm 2^{19}\) 个半字。
- 立即数字段的排列类似于分支指令，以降低硬件成本。

### 分支与跳转综合示例
以下是一个 `while` 循环的汇编及其机器码（十进制 PC 及字段示意）：
```assembly
  80000: Loop: slli x6, x9, 2        # I型
  80004: add  x6, x6, x11            # R型
  80008: lw   x5, 0(x6)              # I型
  80012: bne  x5, x10, Exit          # B型 (偏移16字节)
  80016: addi x9, x9, 1              # I型
  80020: j    Loop                    # J型 (偏移-20字节)
  80024: Exit: ...
```
- `bne x5, x10, 12`：立即数=12（13位编码高12位），目标=80012 + 6×2 = 80024。
- `jal x0, -20`：立即数=-20（21位编码高20位），目标=80020 + (-10×2) = 80000。

## 大立即数 (Large Immediate)

### 32 位常量载入
大多数常数很小，12 位足矣。偶尔需要 32 位常量，比如 `li x10, 0x87654321` 或 `la x10, my_var`。
- 使用 `LUI` (Load Upper Immediate) 写入高 20 位，低 12 位清零。
- 再配合 `ADDI` 设置低 12 位，可两条指令生成任意 32 位值。

**示例：设置 x10 = 0x87654321**
```assembly
lui  x10, 0x87654      # x10 = 0x87654000
addi x10, x10, 0x321   # x10 = 0x87654321
```
**边界情况：0xDEADBEEF**  
`addi` 的 12 位立即数符号位为 1 时会“借位”，因此需预先处理修正：
```assembly
lui  x10, 0xDEADC      # 实际 0xDEADB + 1
addi x10, x10, 0xEEF   # 结果：0xDEADBEEF
```
（即把加载的高20位加1，以抵消符号扩展造成的减量。）

### U 型格式 (U‑Type for “Upper Immediate”)
- 32 位指令字的高 20 位为立即数，仅用 `rd` 一个寄存器字段，无 `rs1`。
- 用于两条指令：
  - **`LUI`**：`rd = imm << 12`
  - **`AUIPC`** (Add Upper Immediate to PC)：`rd = PC + (imm << 12)`

### 绝对跳转 (Jumps to Absolute)
对于更远的跳转，使用 `JALR`（I‑格式）：
- `jalr rd, rs, immediate` 或 `jalr rd, immediate(rs)`
- 将 `PC+4` 存入 `rd`（返回地址），然后 `PC ← rs + immediate`（**绝对地址，不乘以2**）。
- 不同于 `JAL` 的 PC 相对偏移，`JALR` 是基址+偏移绝对寻址。

## RV32 扩展 (RV32 Extensions)

- **RV32I**：基础整数指令集。
- 标准扩展：
  - **M**：整数乘除法 (`mul`, `div`, `rem` 等)
  - **A**：原子指令，用于多核同步 (`amoadd.w`, `amoswap.w` 等)
  - **F**：单精度浮点 (32 位) (`fadd.s`, `fmul.s`, `flw`, `fsw`)
  - **D**：双精度浮点 (64 位)
  - **C**：压缩指令 (16 位编码常见 32 位指令，减小代码体积)
- 常见组合：`RV32IM`、`RV32IMFC`。

## 不同的指令集架构 (Different ISAs)

- **RISC‑V**：开源，模块化，迅速增长。
- **MIPS**：RISC‑V 的商业前身，设计相似。
- **ARM**：广泛应用于移动/嵌入式，指令集版本较多。
- **x86**：Intel/AMD，从 8086 演化至今，CISC 代表。

### RISC‑V 市场份额
据 Semico Research 预测，到 2025 年 RISC‑V CPU 核心累计出货量将达到 **624 亿**，2018‑2025 年复合增长率 (CAGR) 为 146.2%；工业领域将引领，达 167 亿颗。

### MIPS 指令集
- 与 RISC‑V 类似：32 位定长指令，32 个通用寄存器（寄存器 0 恒为 0），32 个浮点寄存器。
- 仅通过 load/store 访问内存。
- 条件分支方式不同：
  - RISC‑V 直接使用 `blt`、`bge` 等。
  - MIPS 用 `slt`/`sltu` 比较并置结果寄存器为 0/1，再用 `beq`、`bne` 完成分支。

### Intel x86 演化里程碑
| 名称 | 年份 | 晶体管数 | 频率 | 特点 |
| :--- | :--- | :--- | :--- | :--- |
| 8086 | 1978 | 29K | 5-10 MHz | 首个 16 位 Intel 处理器，IBM PC / DOS 的基础，1MB 地址空间 |
| 386 | 1985 | 275K | 16-33 MHz | 首个 32 位处理器（IA32），引入平坦寻址，可运行 Unix |

| Core i7 | 2008 | 731M | 1700-3900 MHz | 四核 |

## 总结 (Concluding Remarks)

- **设计原则回顾**
  1. 简单性崇尚规整性
  2. 越小越快
  3. 加速大概率事件
  4. 优秀设计需要权衡
- **软硬件层次**
  编译器 → 汇编器 → 硬件
- **RISC‑V**：RISC ISA 的典型代表，与 x86 等 CISC 形成鲜明对比。
