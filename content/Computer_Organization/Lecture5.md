## 加减法与溢出 (Addition/Subtraction and Overflow)

### 1 位加法器 (1-bit Adder)
一位全加器的逻辑函数为：
- 和 (Sum): \(Sum = a \cdot b' \cdot Cin' + a' \cdot b \cdot Cin' + a' \cdot b' \cdot Cin + a \cdot b \cdot Cin\)
- 进位输出 (Cout): \(Cout = a \cdot Cin + b \cdot Cin + a \cdot b\)

由 1 位 ALU 可级联构成 **32 位 ALU (Arithmetic Logical Unit，算术逻辑单元)**。
- 若操作码 `op = 0`，输出 \(o = a \& b\) (按位与)
- 若 `op = 1`，输出 \(o = a | b\) (按位或)
- 若 `op = 2`，输出 \(o = a + b\) (加法)

### 溢出 (Overflow)
- **无符号数溢出**：当最高位产生的进位无法被容纳（即超出表示范围）时发生。
- **有符号数溢出**：当结果的最高位与左边所有位不一致时发生。具体表现为：
  - 两个正数相加得到负数结果
  - 两个负数相加得到正数结果
  - 正数与负数相加**永远不会**溢出
- 8 位有符号整数范围：\(-128 \sim 127\)；8 位无符号整数范围：\(0 \sim 255\)。

### 整数加减法与溢出的关系
**示例 1：7 + 6**
- 若结果超出表示范围则溢出。
- 有符号加法溢出条件：
  - 两个正数相加得负数
  - 两个负数相加得正数
  - 正负相加，无溢出

**示例 2：7 – 6**
减法通过加上第二个操作数的相反数来实现：\(7 - 6 = 7 + (-6)\)
```
+7: 0000 0000 … 0000 0111
-6: 1111 1111 … 1111 1010
+1: 0000 0000 … 0000 0001
（按位取反加一得到 -6 的补码表示）
```
- 有符号减法溢出条件：
  - 从负数中减去正数，结果符号为 0（正）→ 溢出
  - 从正数中减去负数，结果符号为 1（负）→ 溢出
  - 同号相减，无溢出

### 有符号数溢出的具体判断（加减统一）
- 若相加的两操作数符号不同，则永不溢出。
- 若符号相同，且结果符号与操作数符号不同，则溢出。

**补充示例**：
```
12 + 3 = 15          120 + 15 = 135       12 - 3 = 9           -100 - 50 = -150
  00001100              01111000              00001100              10011100
+ 00000011            + 00001111            + 11111101            + 11001110
-------------         -------------         -------------         -------------
  00001111              10000111              00001001              01101010
(无溢出)             (有溢出, 135 > 127)    (无溢出)            (有溢出, -150 < -128)
```

### 溢出检测的 RISC‑V 代码
对于**有符号加法**，可通过检查符号位来判断溢出：
```assembly
# t0 = sum, t1/t2 为操作数
add  t0, t1, t2
xor  t3, t1, t2       # 检查两操作数符号是否不同
slt  t3, t3, zero     # 若符号不同，t3=1
bne  t3, zero, No_overflow   # 符号不同则无溢出
xor  t3, t0, t1       # 比较和与操作数符号
slt  t3, t3, zero
bne  t3, zero, Overflow      # 符号不同则发生溢出
```
对于**无符号加法**（溢出即产生进位）：
```assembly
# t0 = sum, t1/t2 为操作数
add  t0, t1, t2
xori t3, t1, -1       # t3 = NOT t1 (即 2^32 - 1 - t1)
sltu t3, t3, t2       # (2^32 - 1 - t1) < t2 ?
bne  t3, zero, Overflow # 若成立，则 t1 + t2 > 2^32-1，溢出
```

### 多媒体算术：饱和运算 (Arithmetic for Multimedia – Saturating Operation)
- 图形与媒体处理常对 8 位或 16 位数据向量进行操作。
- 使用 64 位加法器，并分割进位链，可同时处理 8×8 位、4×16 位或 2×32 位向量，即 **SIMD (Single-Instruction, Multiple-Data，单指令多数据)**。
- **饱和运算 (Saturating Operations)**：当结果溢出时，将其钳位到最大可表示值，而非像补码运算那样回卷（wrap around）。
  - 对比：补码算术是模运算。
  - 典型应用：音视频处理中的音量、亮度调节。

## 整数乘法 (Integer Multiplication)

### 乘法算法与实现 (Multiplication Algorithms and Implementation)

#### 基本乘法硬件
模仿手工乘法：
```
     1000   (被乘数)
   × 1001   (乘数)
   --------
     1000
    0000
   0000
  1000
 ---------
  1001000   (乘积，位数＝被乘数位数＋乘数位数)
```
每一步：被乘数左移，检查乘数的当前位，若为 1 则将移位后的被乘数加到积上。

#### 慢速乘法器示例（4 位）
计算 \(2_{10} \times 7_{10}\)，即 \(0010_2 \times 0111_2\)。

| 迭代 | 步骤 | 乘数 | 被乘数 | 乘积 |
|:---:|:---|:---:|:---:|:---:|
| 0 | 初始值 | 0111 | 0000 0010 | 0000 0000 |
| 1 | 乘数最低位=1 → 积=积+被乘数 | 0111 | 0000 0010 | 0000 0010 |
| | 被乘数左移，乘数右移 | 0011 | 0000 0100 | 0000 0010 |
| 2 | 乘数最低位=1 → 积=积+被乘数 | 0011 | 0000 0100 | 0000 0110 |
| | 被乘数左移，乘数右移 | 0001 | 0000 1000 | 0000 0110 |
| 3 | 乘数最低位=1 → 积=积+被乘数 | 0001 | 0000 1000 | 0000 1110 |
| | 被乘数左移，乘数右移 | 0000 | 0001 0000 | 0000 1110 |
| 4 | 乘数最低位=0 → 无加 | 0000 | 0001 0000 | 0000 1110 |
| | 被乘数左移，乘数右移 | 0000 | 0010 0000 | 0000 1110 |

结果：\(00001110_2 = 14_{10}\)。注意乘积需 8 位。

#### 优化乘法器 (Optimized Multiplier)
- 观察到：被乘数一半位始终为 0，64 位加法器浪费；乘积低位一旦形成就不再改变。
- 改进：**不左移被乘数，而是右移乘积**，并将乘数放在乘积寄存器的右半部分，节省空间。

优化后的流程（仍以 \(0010 \times 0111\) 为例）：

| 迭代 | 被乘数 | 乘积 (含乘数) | 操作 |
|:---:|:---:|:---:|:---|
| 0 | 0010 | 0000 **0111** | 初始，乘数在低 4 位 |
| 1 | 0010 | 0010 0111 | 乘积最低位=1，左半加被乘数 |
| | | 0001 0011 | 乘积右移一位 |
| 2 | 0010 | 0011 0011 | 最低位=1，左半加被乘数 |
| | | 0001 1001 | 乘积右移一位 |
| 3 | 0010 | 0011 1001 | 最低位=1，左半加被乘数 |
| | | 0001 1100 | 乘积右移一位 |
| 4 | 0010 | 0000 1110 | 最低位=0，仅右移一位 |

最终乘积寄存器内容为 `0000 1110`，即 14。整个过程只需要一个 32 位 ALU 和 64 位乘积寄存器。

#### 更快的乘法器 (Faster Multiplier)
- 前面的算法需要时钟确保加法完成后再移位。
- 可采用**多个流水线加法器**并行计算部分积，用组合逻辑快速传播进位，无需等待时钟 —— 速度更快，但晶体管开销大。
- 可以在多个乘法间流水处理，进一步提高吞吐量。

### 有符号整数乘法 (Multiplication for Signed Integers)
- 方法一：将负数转换为正数，计算乘积，再调整符号。例如 \((-7) \times (-6)\)：
  - \(|-7| = 7 = 0111_2\), \(|-6| = 6 = 0110_2\)
  - \(7 \times 6 = 0111_2 \times 0110_2 = 101010_2 = 42\)
  - 结果为正，取 42。
- 方法二：直接使用补码运算，在移位时对符号进行扩展（算术右移），可统一处理。

### RISC‑V 乘法指令
RISC‑V 提供四条乘法指令（属于 M 扩展）：
- `mul rd, rs1, rs2`：乘法，取乘积的低 32 位存入 `rd`。
- `mulh rd, rs1, rs2`：有符号乘法高位，返回乘积的高 32 位（视为有符号数）。
- `mulhu rd, rs1, rs2`：无符号乘法高位，返回乘积的高 32 位（视为无符号数）。
- `mulhsu rd, rs1, rs2`：有符号×无符号乘法高位，返回乘积高 32 位（一个操作数有符号，另一个无符号）。

## 整数除法 (Integer Division)

### 除法算法与硬件
基本除法采用**恢复余数法** (Restoring Division)，类似手算长除：
- 检查除数与当前余数部分的大小。
- 若除数 ≤ 余数，商位为 1，相减得新余数。
- 否则商位为 0，恢复原余数，并拉下下一位被除数。

#### 除法示例 1：4 位除法 \(7_{10} \div 2_{10}\) (0111 ÷ 0010)

| 迭代 | 步骤 | 商 | 除数 | 余数 |
|:---:|:---|:---:|:---:|:---|
| 0 | 初始值 | 0000 | 0010 0000 | 0000 0111 |
| 1 | 余=余-除 | 0000 | 0010 0000 | 1110 0111 |
| | 余<0 → 恢复，商0 | 0000 | 0010 0000 | 0000 0111 |
| | 除数右移 | 0000 | 0001 0000 | 0000 0111 |
| 2 | 余=余-除 | 0000 | 0001 0000 | 1111 0111 |
| | 余<0 → 恢复，商0 | 0000 | 0001 0000 | 0000 0111 |
| | 除数右移 | 0000 | 0000 1000 | 0000 0111 |
| 3 | 余=余-除 | 0000 | 0000 1000 | 1111 1111 |
| | 余<0 → 恢复，商0 | 0000 | 0000 1000 | 0000 0111 |
| | 除数右移 | 0000 | 0000 0100 | 0000 0111 |
| 4 | 余=余-除 | 0000 | 0000 0100 | 0000 0011 |
| | 余≥0 → 商1 | 0001 | 0000 0100 | 0000 0011 |
| | 除数右移 | 0001 | 0000 0010 | 0000 0011 |
| 5 | 余=余-除 | 0001 | 0000 0010 | 0000 0001 |
| | 余≥0 → 商1 | 0011 | 0000 0010 | 0000 0001 |
| | 除数右移 | 0011 | 0000 0001 | 0000 0001 |

结果：商 = 0011 (3)，余数 = 0001 (1)。符合 \(7 \div 2 = 3 \cdots 1\)。

#### 除法示例 2：8 位被除数 / 4 位除数 \(74_{10} \div 8_{10}\) (01001010 ÷ 1000)
```
迭代 商       除数        余数       说明
0   0000   10000000   01001010   初始
1   0000   01000000   01001010   余=余-除 负，恢复，除数右移
2   0001   00100000   00001010   余≥0，商1；除数右移
3   0010   00010000   00001010   余=余-除 负，恢复，商0；除数右移
4   0100   00001000   00001010   余=余-除 负，恢复，商0；除数右移
5   1001   00000100   00000010   余≥0，商1；除数右移
```
最终商 1001 (9)，余数 00000010 (2)。

#### 优化除法器 (Optimized Divider)
- 与优化乘法器类似，被除数/余数与商合用同一个移位寄存器，每步进行余数减除数，然后移位。
- 硬件可复用乘法器的数据通路，节省面积。

### 有符号除法 (Signed Division)
- 通常将操作数取绝对值，相除后再调整符号。
- 规定：**余数的符号与被除数相同**，商的符号取决于操作数符号：
  - 同号为正，异号为负。
- 示例：
  - \(+7 \div +2\)：商=+3，余=+1
  - \(-7 \div +2\)：商=-3，余=-1
  - \(+7 \div -2\)：商=-3，余=+1
  - \(-7 \div -2\)：商=+3，余=-1
- 这样就保证了等式：\(\text{被除数} = \text{除数} \times \text{商} + \text{余数}\) 始终成立。

### 更快的除法 (Faster Division)
- 除法无法像乘法那样直接用组合逻辑一次性完成所有部分积的相加，因为减法依赖于余数的符号。
- 更快的除法算法（如 SRT 除法）每个步骤可产生多位商，但仍需多步迭代。

### RISC‑V 除法指令
RISC‑V 提供四条除法与余数指令（M 扩展）：
- `div rd, rs1, rs2`：有符号除法，商存入 `rd`。
- `rem rd, rs1, rs2`：有符号求余数。
- `divu rd, rs1, rs2`：无符号除法。
- `remu rd, rs1, rs2`：无符号求余数。
- 溢出（如除以零）**不触发异常**，而是返回一个预定义结果，以保证常见无错情况下的执行速度。
