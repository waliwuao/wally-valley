## 第一章 : 从 Java 到 CPU：重新认识计算机的核心运算部件

### 1.1 学习 CPU 组成原理的意义

你已习惯于使用 Java 编写各类应用程序。例如：

```java
public class Example {
    public static int add(int a, int b) {
        return a + b;
    }
    public static void main(String[] args) {
        int x = 5;
        int y = 10;
        int z = add(x, y);
        System.out.println(z);
    }
}
```

按下运行按钮后，这段代码经过编译，最终转化为一系列最基础的机器指令，由中央处理器逐条执行。中央处理器是计算机的运算与控制核心，它仅识别二进制编码的 0 和 1，却能够执行复杂的算术逻辑运算、控制程序流程、管理内存访问。若只掌握高级语言而不理解底层硬件的工作机制，当面临性能调优或专用硬件设计任务时，将缺乏必要的认知基础。

本教程的目标是帮助读者揭示这一底层机制。你将看到：寄存器、算术逻辑单元、程序计数器、内存、栈等概念如何通过 RISC-V 指令集架构协同工作。

### 1.2 RISC-V 的定义与选择理由

RISC-V（发音为 "risk-five"）是一套开放、免费的指令集架构标准，由加州大学伯克利分校研究团队于 2010 年发布。其设计初衷面向教学与研究，但因指令集简洁规整、扩展灵活，现已被广泛应用于嵌入式微控制器、物联网设备、人工智能加速器乃至高性能计算领域。

与 Intel 的 x86 或 ARM 架构不同，RISC-V 本身并非一款具体的处理器芯片，而是一份公开的指令集规范文档。任何组织或个人均可依据该规范设计并实现自己的处理器，无需支付专利授权费用。对于学习者而言，RISC-V 的基础整数指令集仅包含约 40 条必需指令，且所有指令长度固定为 32 位，硬件译码与流水线设计难度远低于 x86 或 ARM，因此是用 Verilog 实践 CPU 设计的理想选择。

**RISC-V 核心设计原则**  
- **规整性简化硬件**：基础指令长度固定为 32 位，指令字段位置高度统一，译码电路可以规整实现。  
- **模块化与可扩展性**：基础整数指令集（RV32I）为必选模块，乘除法（M 扩展）、浮点运算（F/D 扩展）等为可选模块。  
- **软件与硬件间的清晰接口**：定义了标准化的寄存器用途约定与内存模型，保证不同编译器生成的代码能够相互调用。

在学习后续内容之前，请先建立一个宏观认知：**一个 RISC-V 处理器核心由寄存器堆、算术逻辑单元、控制器、程序计数器以及内存访问接口构成**。下一章将首先介绍处理器内部最重要的数据暂存部件——寄存器。

## 第二章 : RISC-V 的硬件资源：寄存器与内存布局

### 2.1 寄存器的概念与访问速度

在 Java 程序中可以声明大量局部变量。但在处理器内部，**参与运算的数据必须首先被搬移至名为“寄存器”的高速存储单元中**。寄存器是集成在处理器芯片内部的小容量存储器，其访问延迟通常在纳秒级以下。

> 类比说明：如果把处理器比作一名正在工作的厨师，那么寄存器相当于厨师面前的案板与调料架——所有处理动作均在此完成，伸手即得。而内存则相当于厨房角落里的大容量冰箱，虽然存储空间充足，但每次存取食材都需要走过去拉开冰箱门，所需时间远超案板操作。

RISC-V 架构标准定义了 **32 个通用寄存器**，在汇编语言中以编号 `x0` 到 `x31` 表示。在 32 位架构（RV32I）中，每个寄存器的宽度为 32 比特（4 字节）。

### 2.2 寄存器的应用二进制接口命名与用途

虽然硬件层面仅识别 `x0` 至 `x31` 的编号，但在编写汇编程序时，通常使用一套具有语义的 **ABI 名称**（Application Binary Interface，应用二进制接口）。该命名规范规定了每个寄存器在函数调用过程中的预期用途，是保证不同模块代码能够正确协作的基础约定。

**RISC-V 通用寄存器列表（RV32I）**

| 寄存器编号 | ABI 名称 | 功能描述 | 保存责任方 |
| :--- | :--- | :--- | :--- |
| **x0** | **zero** | 硬件强制为 0。写入该寄存器的数据将被丢弃，读取永远返回 0。常用于清零操作或生成常数 0。 | —— |
| **x1** | **ra** | 返回地址寄存器。执行过程调用指令时，自动保存返回地址（下一条指令的地址）。 | 调用者保存 |
| **x2** | **sp** | 栈指针寄存器。始终指向当前栈空间的顶部（栈向低地址方向增长）。 | 被调用者保存 |
| **x3** | **gp** | 全局指针寄存器。用于访问静态数据区中的全局变量。 | —— |
| **x4** | **tp** | 线程指针寄存器。用于多线程环境中的线程局部存储访问。 | —— |
| **x5 - x7** | **t0 - t2** | 临时寄存器。过程内部可任意使用，调用子过程后其值可能被破坏。 | 调用者保存 |
| **x8** | **s0 / fp** | 保存寄存器，亦可作为帧指针寄存器使用。 | 被调用者保存 |
| **x9** | **s1** | 保存寄存器。 | 被调用者保存 |
| **x10 - x11** | **a0 - a1** | 函数参数寄存器，同时用于存放函数返回值。 | 调用者保存 |
| **x12 - x17** | **a2 - a7** | 函数参数寄存器，用于传递额外参数。 | 调用者保存 |
| **x18 - x27** | **s2 - s11** | 保存寄存器。若过程内需要使用，必须先将原值保存至栈中。 | 被调用者保存 |
| **x28 - x31** | **t3 - t6** | 临时寄存器。用途同 t0~t2。 | 调用者保存 |

**关键概念：调用者保存与被调用者保存**

- **调用者保存（Caller-saved）**：寄存器 `ra`、`t0`-`t6`、`a0`-`a7` 属于此类。调用者在发起过程调用前，若这些寄存器中含有后续仍需使用的数据，必须由调用者自行将其保存到栈中。被调用过程可能会随意修改这些寄存器。

- **被调用者保存（Callee-saved）**：寄存器 `sp`、`s0`-`s11` 属于此类。被调用过程若需要使用这些寄存器，必须在过程入口处先将原值保存到栈中，并在返回前恢复原值。调用者可以信赖这些寄存器的值在调用前后保持不变。

### 2.3 内存布局：代码段、数据段与栈空间

程序代码、大数组、全局变量等数据存储在内存中。RISC-V 程序运行时的典型内存布局遵循冯·诺依曼结构模型，具体分区如下：

| 内存区域 | 用途说明 | RISC-V 相关特点 |
| :--- | :--- | :--- |
| **Text Segment（文本段）** | 存放编译生成的二进制机器指令，通常为只读。 | 程序计数器在此区域内顺序或跳转取指。 |
| **Static Data Segment（静态数据段）** | 存放全局变量、`static` 修饰的局部变量、字符串字面量。 | 通过全局指针寄存器 `gp` 配合偏移量访问。 |
| **Heap（堆）** | 动态内存分配区域。对应于 C 语言中的 `malloc` 或 Java 中的 `new` 所分配的空间。 | 向高地址方向增长。 |
| **Stack（栈）** | 存放过程调用栈帧（返回地址、局部数组、保存的寄存器等）。 | 由栈指针寄存器 `sp` 管理，**向低地址方向增长**。 |

> **注意**：在 RISC-V 基础整数指令集中，内存按字节编址。加载字指令（`lw`）和存储字指令（`sw`）通常要求地址按 4 字节对齐，非对齐访问可能触发异常或由硬件拆分为多次内存操作，具体行为取决于处理器实现。

## 第三章 : RISC-V 指令集：汇编语言与指令格式

### 3.1 指令分类与功能总览

掌握处理器硬件资源后，下一步是学习如何通过指令指挥处理器工作。RISC-V 汇编语言是机器指令的人类可读文本形式。**所有指令均可归纳为三种基本操作类型：数据传送、算术逻辑运算、控制流跳转。**

下表汇总了 RV32I 基础整数指令集中最常用的指令及其功能描述。

| 类别 | 指令名称与示例 | 操作描述 |
| :--- | :--- | :--- |
| **算术运算** | 寄存器加法 `add x5, x6, x7` | 将寄存器 x6 与 x7 的值相加，结果写入 x5。 |
| | 寄存器减法 `sub x5, x6, x7` | 将寄存器 x6 的值减去 x7 的值，结果写入 x5。 |
| | 立即数加法 `addi x5, x6, 100` | 将寄存器 x6 的值与立即数 100 相加，结果写入 x5。 |
| | 乘法 `mul x5, x6, x7` | 将寄存器 x6 与 x7 的值相乘，结果写入 x5（需 M 扩展支持）。 |
| **逻辑运算** | 按位与 `and x5, x6, x7` | 将寄存器 x6 与 x7 的值按位进行逻辑与运算，结果写入 x5。 |
| | 按位或（立即数） `ori x5, x6, 0xff` | 将寄存器 x6 的值与立即数 0xff 按位进行逻辑或运算，结果写入 x5。 |
| | 按位异或（立即数） `xori x5, x6, -1` | 将寄存器 x6 的值与立即数 -1（即全 1 位模式）按位异或，效果等同于按位取反。 |
| **移位运算** | 逻辑左移（立即数） `slli x5, x6, 2` | 将寄存器 x6 的值左移 2 位，低位补 0，结果写入 x5。 |
| | 逻辑右移（立即数） `srli x5, x6, 2` | 将寄存器 x6 的值右移 2 位，高位补 0，结果写入 x5。 |
| | 算术右移（立即数） `srai x5, x6, 2` | 将寄存器 x6 的值右移 2 位，高位以原最高位（符号位）填充，结果写入 x5。 |
| **内存访问** | 加载字 `lw x5, 0(x6)` | 从内存地址 (x6+0) 处读取 4 字节，符号扩展至 32 位后存入 x5。 |
| | 存储字 `sw x5, 8(sp)` | 将寄存器 x5 的低 4 字节写入内存地址 (sp+8) 处。 |
| | 加载字节（有符号） `lb x5, 0(x6)` | 从内存地址 (x6+0) 处读取 1 字节，符号扩展至 32 位后存入 x5。 |
| | 加载字节（无符号） `lbu x5, 0(x6)` | 从内存地址 (x6+0) 处读取 1 字节，高位补 0 扩展至 32 位后存入 x5。 |
| **条件分支** | 相等时分支 `beq x5, x6, label` | 若 x5 的值等于 x6 的值，则跳转到标号 label 处执行。 |
| | 不相等时分支 `bne x5, x6, label` | 若 x5 的值不等于 x6 的值，则跳转到标号 label 处执行。 |
| | 小于时分支 `blt x5, x6, label` | 若 x5 的值小于 x6 的值（有符号比较），则跳转到标号 label 处执行。 |
| | 大于等于时分支 `bge x5, x6, label` | 若 x5 的值大于或等于 x6 的值（有符号比较），则跳转到标号 label 处执行。 |
| **无条件跳转** | 跳转并链接 `jal x1, label` | 将下一条指令的地址（返回地址）存入 x1 寄存器，然后跳转到标号 label 处执行。 |
| | 寄存器跳转并链接 `jalr x0, 0(x1)` | 跳转到 x1 寄存器所指向的地址处执行（常用于过程返回）。 |

### 3.2 指令编码格式：32 位二进制指令的结构

指令编码格式是设计处理器硬件的关键内容。使用 Verilog 实现的处理器译码器必须根据 32 位二进制指令中的特定字段来判断操作类型。

RISC-V 将 32 位指令划分为六种基本格式：R 型、I 型、S 型、B 型、U 型、J 型。不同格式由 **opcode（操作码）** 字段（位于最低 7 位）区分，`funct3` 和 `funct7` 字段进一步指定具体操作。

| 格式类型 | 第 31 至 25 位 | 第 24 至 20 位 | 第 19 至 15 位 | 第 14 至 12 位 | 第 11 至 7 位 | 第 6 至 0 位 | 用途 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **R 型** | funct7 | rs2 | rs1 | funct3 | rd | opcode | 寄存器-寄存器运算（如 `add`、`sub`、`and`） |
| **I 型** | imm[11:0] | | rs1 | funct3 | rd | opcode | 立即数运算、加载指令、`jalr` |
| **S 型** | imm[11:5] | rs2 | rs1 | funct3 | imm[4:0] | opcode | 存储指令（如 `sw`、`sb`） |
| **B 型** | imm[12|10:5] | rs2 | rs1 | funct3 | imm[4:1|11] | opcode | 条件分支指令（如 `beq`、`bne`） |
| **U 型** | imm[31:12] | | | | rd | opcode | 高位立即数加载（`lui`、`auipc`） |
| **J 型** | imm[20|10:1|11|19:12] | | | | rd | opcode | 无条件跳转（`jal`） |

**设计特点：字段位置的高度复用**

值得关注的是，**rs1（源寄存器 1）、rs2（源寄存器 2）、rd（目的寄存器）** 字段在 R、I、S、B 四种格式中的位置高度一致。例如，rs1 字段始终位于第 19 至 15 位，rs2 位于第 24 至 20 位。这种规整的字段排列使得处理器译码阶段可以提前并行读取寄存器堆，无需等待指令类型判定完成，从而简化了硬件设计并提升了时序性能。

**示例：指令 `add x5, x6, x7` 的编码过程**

- 指令格式：R 型  
- opcode：`0110011`  
- funct3：`000`  
- funct7：`0000000`  
- rs1：x6（二进制 `00110`）  
- rs2：x7（二进制 `00111`）  
- rd：x5（二进制 `00101`）

将以上字段按格式拼接，得到 32 位机器码：  
`0000000 00111 00110 000 00101 0110011`  
对应的十六进制表示为 `0x007302B3`。

### 3.3 分支与跳转寻址机制

Java 中的 `if` 语句和循环结构在编译后转化为条件分支指令。RISC-V 条件分支的目标地址采用 **PC 相对寻址** 方式计算：

```
目标地址 = 当前指令地址 (PC) + 立即数偏移 * 2
```

**立即数偏移为何乘以 2**  
RISC-V 基础指令均为 4 字节对齐，即所有指令地址的最低两位恒为 `00`。为在有限位数内表达更大的跳转范围，分支指令将偏移量以 **半字（2 字节）** 为单位编码在立即数字段中。执行时，硬件将立即数左移 1 位（乘以 2）还原为字节地址偏移。因此，B 型格式中 12 位立即数可表达 +/- 4 KiB 的跳转范围。

**无条件跳转指令说明**

| 指令形式 | 功能说明 |
| :--- | :--- |
| `jal rd, label` | 将返回地址（PC+4）存入 rd 寄存器，并跳转至 label 地址。 |
| `j label` | 伪指令，等价于 `jal x0, label`，不保存返回地址。 |
| `jalr rd, offset(rs1)` | 跳转至地址 (rs1 + offset)，并将返回地址存入 rd。常用于过程返回：`jalr x0, 0(ra)`。 |

### 3.4 大立即数的合成方法

I 型指令中的立即数字段宽度仅为 12 位。若需要将 32 位常量（例如地址 `0x12345678`）加载到寄存器中，必须通过两条指令组合实现。

| 指令 | 功能说明 | 示例操作效果 |
| :--- | :--- | :--- |
| `lui rd, imm` | 将 20 位立即数写入 rd 寄存器的高 20 位，低 12 位清零。 | `lui x5, 0x12345` → x5 = 0x12345000 |
| `addi rd, rs1, imm` | 将 12 位立即数与 rs1 寄存器值相加，结果写入 rd。 | `addi x5, x5, 0x678` → x5 = 0x12345678 |

> **补充说明**：若低 12 位立即数的最高位（第 11 位）为 1，`addi` 指令会将其符号扩展至 32 位，导致加法结果实际上减去了一个补码修正量。汇编器在处理伪指令 `li x5, 0x12345678` 时，会自动调整为 `lui` 加载值加 1，再配合 `addi` 使用负偏移量，以确保最终结果正确。

## 第四章 : 过程调用与栈管理

高级语言中的函数或方法，在汇编层面被称为**过程**。理解过程调用机制是贯通软件与硬件的关键环节。

### 4.1 过程调用的标准六步骤

无论过程的功能多么复杂，RISC-V 过程调用均遵循以下六个标准步骤。可使用口诀 **“传参跳转开栈帧，执行存值复返还”** 辅助记忆：

1. **传递参数**：将实参存入 `a0` 至 `a7` 参数寄存器。若参数数量超过 8 个，则剩余参数通过栈传递。
2. **跳转至过程入口**：执行 `jal ra, 过程名` 指令，将返回地址保存到 `ra` 寄存器并跳转。
3. **分配栈帧**：在过程入口处减小栈指针 `sp`，在栈上为局部变量和待保存寄存器开辟空间。
4. **执行过程体**：完成过程的核心功能代码。
5. **放置返回值**：将返回值存入 `a0` 和 `a1` 寄存器。
6. **释放栈帧并返回**：恢复 `sp` 至调用前位置，执行 `jalr x0, 0(ra)` 返回调用点。

### 4.2 栈的入栈与出栈操作

栈是内存中遵循后进先出原则的特殊区域，由栈指针寄存器 `sp` 管理。`sp` 始终指向当前栈顶（即最后一个被使用的位置，低地址端）。

- **入栈（开辟空间）**：`addi sp, sp, -N` （栈指针向低地址移动 N 字节）
- **出栈（释放空间）**：`addi sp, sp, +N` （栈指针向高地址移动 N 字节）

在开辟空间后，可使用存储指令（如 `sw`）将寄存器数据保存到栈中。例如，`sw ra, 12(sp)` 将返回地址寄存器保存到栈顶偏移 12 字节处。

### 4.3 叶子过程与非叶子过程实例

#### 叶子过程

**定义**：叶子过程是指在其内部不再调用任何其他过程的过程。

**特点**：无需保存返回地址 `ra`，因为该寄存器的值不会被后续调用覆盖；仅需按需保存使用的 `s0`-`s11` 寄存器。

**示例**：加法函数 `int add(int a, int b)` 的汇编实现

```asm
# 输入参数：a0 = a, a1 = b
# 返回值：a0 = a + b
add_func:
    add a0, a0, a1       # 将 a0 与 a1 相加，结果存入 a0（即返回值）
    ret                  # 伪指令，等价于 jalr x0, 0(ra)，返回调用者
```

#### 非叶子过程与递归实现

**定义**：非叶子过程是指在其内部又调用了其他过程（包括自身递归调用）的过程。

**特点**：必须将返回地址 `ra` 保存到栈中，因为后续的过程调用会覆盖 `ra` 的值；同时，需要在调用前保护即将作为实参传递或后续仍需使用的寄存器。

**示例**：递归计算阶乘 `int fact(int n)` 的汇编实现

```asm
# 函数原型：int fact(int n)
# 输入参数：a0 = n
# 返回值：a0 = n!
fact:
    addi sp, sp, -8      # 步骤1：分配 8 字节栈空间
    sw ra, 4(sp)         # 步骤2：保存返回地址 ra
    sw a0, 0(sp)         # 步骤3：保存参数 n（调用期间 a0 将被修改）

    li t0, 1
    ble a0, t0, base_case # 步骤4：若 n <= 1，跳至基准情况

    # 递归情况：计算 n * fact(n-1)
    addi a0, a0, -1      # 步骤5：实参 n-1 放入 a0
    jal ra, fact         # 步骤6：调用 fact(n-1)
                         # 返回后 a0 中为 fact(n-1) 的结果

    lw t1, 0(sp)         # 步骤7：从栈中恢复原始参数 n 至 t1
    mul a0, a0, t1       # 步骤8：计算 fact(n-1) * n，结果存入 a0
    j exit

base_case:
    li a0, 1             # 步骤9：基准情况，返回 1

exit:
    lw ra, 4(sp)         # 步骤10：恢复返回地址 ra
    addi sp, sp, 8       # 步骤11：释放栈空间
    ret                  # 步骤12：返回调用者
```

**递归调用过程中的栈帧变化（以 fact(3) 为例）**

| 调用深度 | 栈中存放内容（栈指针 sp 指向当前帧） | 操作说明 |
| :--- | :--- | :--- |
| 进入 `fact(3)` | [保存的 ra（指向主调函数）、参数值 3] | 保存主调函数的返回地址及参数 n=3 |
| 进入 `fact(2)` | [保存的 ra（指向 fact(3)）、参数值 2]、[上一层栈帧数据...] | 保存 ra 及 n=2 |
| 进入 `fact(1)` | [保存的 ra（指向 fact(2)）、参数值 1]、[上两层栈帧数据...] | 保存 ra 及 n=1；满足基准条件，返回 1 |
| 返回 `fact(2)` | 栈帧弹出 | 计算 2 * 1 = 2，存入 a0 |
| 返回 `fact(3)` | 栈帧弹出 | 计算 3 * 2 = 6，存入 a0 |

## 第五章 : 汇编指令到机器码的转换与处理器解读过程

理解了汇编指令及其编码格式后，下一个问题是：当编译生成的机器码 `0x007302B3` 被送入处理器时，硬件电路如何识别并执行它。这是本教程中与 Verilog 实现最直接相关的部分。

### 5.1 取指与译码阶段

处理器内部设有一个**程序计数器**寄存器，其中存放着当前待执行指令的内存地址。

1. **取指阶段**：处理器通过内存总线向指令存储器发出读请求，请求地址为程序计数器当前值。指令存储器返回对应的 32 位数据（例如 `0x007302B3`）。

2. **译码阶段**：处理器中的译码器电路（在 Verilog 中通常由组合逻辑 `case` 语句或查找表实现）检查该 32 位数据的 `opcode` 字段（最低 7 位）。
   - `opcode` 为 `0110011`，译码器判定该指令为 **R 型算术指令**。
   - 根据 R 型格式定义，译码器提取以下字段：
     - `rs1`：第 19 至 15 位 → `00110`（对应 x6）
     - `rs2`：第 24 至 20 位 → `00111`（对应 x7）
     - `rd`：第 11 至 7 位 → `00101`（对应 x5）
   - 检查 `funct3` 和 `funct7` 字段，均为 `000` 和 `0000000`，译码器判定具体操作为 **加法**。

### 5.2 执行与写回阶段

- **执行阶段**：译码器产生的控制信号使能寄存器堆的读端口，读出 x6 和 x7 中存储的数值（例如 10 和 20）。控制信号同时配置算术逻辑单元执行加法运算。算术逻辑单元输出运算结果 30。

- **写回阶段**：控制信号使能寄存器堆的写端口，在下一个时钟上升沿将计算结果 30 写入目的寄存器 x5。

至此，一条 `add x5, x6, x7` 指令执行完毕。随后程序计数器增加 4，指向下一条顺序指令地址。

### 5.3 条件分支指令的执行机制

条件分支指令（如 `beq`）的执行流程略有不同。译码后，处理器并行执行两项操作：
1. 比较 `rs1` 与 `rs2` 寄存器中的值是否相等。
2. 计算分支目标地址：`当前 PC + 立即数偏移 * 2`。

若比较结果为真（相等），处理器将**刷新流水线**（即丢弃已提前取出的顺序下一条指令），并在下一个时钟周期将程序计数器更新为目标地址，从而实现程序控制流的跳转。

### 5.4 规整指令格式的硬件优势

回顾前述六种指令格式，可以观察到 RISC-V 编码设计对硬件实现的友好性：
- **寄存器字段位置固定**：无论在何种格式中，`rs1` 和 `rs2` 字段的位位置几乎不变。这意味着寄存器堆的读地址连线可以直接与指令特定位连接，无需根据指令类型插入多路选择器进行重定向，降低了译码逻辑的复杂度。
- **立即数重构逻辑规整**：虽然 S 型和 B 型格式将立即数位分散在不同位置，但符号扩展的最高位始终映射到指令的第 31 位，使得立即数重构电路可以采用相对统一的硬件结构实现。
